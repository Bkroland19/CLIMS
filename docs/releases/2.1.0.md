# CLIMS 2.1.0

Version 2.1.0 adds the orders and hotspot activation workflows, expands the mobile field application, and updates authentication and deployment.

## Included in this release

- Store-scoped orders API, order workflow, and distribution-map integration.
- VHT hotspot submission, district verification, activation, rejection, and notifications.
- Mobile field application updates.
- Authentication profile fields, user sessions, refresh tokens, and sign-in using unique identifiers.
- Executable Swagger UI with session-aware authentication.
- SeaweedFS object storage with a persistent production volume.
- Deployment of SeaweedFS alongside the application, with compatibility for older release bundles.
- Makefile support for macOS, Linux, and Windows.

## Upgrade from 2.0.1

Back up PostgreSQL before upgrading. The backend applies migrations 5 through 12 at startup, adding profile context, orders, hotspot review, and session tables. Existing application data remains in the production database volume; do not rerun the legacy seed import.

Usernames and normalized phone numbers become unique login identifiers. For duplicates, the oldest account keeps the identifier. Later usernames receive a suffix and duplicate phone numbers are cleared; the original values are retained in `previous_username` and `previous_phone_number` for administrator review.

Set nonempty `S3_ACCESS_KEY` and `S3_SECRET_KEY` in the server's `shared/prod.env` before deployment. The deployment builds and starts SeaweedFS on the internal Compose network and stores its data in a dedicated volume. Its ports are not published publicly.

The release workflow runs CI, publishes backend/frontend/mobile images and digest manifests, then deploys to the configured `prod` server. See [the release guide](../releases.md) for configuration and retry instructions. Database migrations are not automatically reversed if deployment fails; recovery may require restoring the pre-upgrade backup.

The mobile image exports JavaScript bundles and assets; it does not contain signed native application packages. The configured public API URL is embedded at build time.
